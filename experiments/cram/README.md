# CRAM-style energy on 8×8 N-Queens (CPU, standard library)

A small CPU reimplementation of the idea in CRAM (Compact Reasoning Associative Memory): a pairwise Hopfield–Tank energy whose costs are learned from solved puzzles by pseudolikelihood, used here as a verifier (accept a complete board iff its energy is at or below a threshold fitted on training solutions) and as a solver (clamp a few queens, descend the energy one cell at a time). It follows §3 and Table 1 of Hoover, Blayney and Whittington, [Classical Energies Learn to Reason 1,000× Faster than Looped Models](https://arxiv.org/abs/2611.17309) (arXiv:2611.17309), with the [Prefrontal blog post](https://prefrontal.ai/news/cram) and the official GPU code at [Prefrontal-AI/CRAM](https://github.com/Prefrontal-AI/CRAM) as references. It is the prototype proposed in [RFC 0002](../../rfcs/0002-energy-based-constraint-reasoners-cram.md).

**This is a simplified CPU reimplementation, not a reproduction.** It does not reproduce, and makes no claim about, the paper's H200 timings, its Sudoku-Extreme or Maze-Unique results, or its N-Queens numbers on Baek et al.'s test set. The numbers below were measured here and apply only to this code and protocol.

## Model

| Piece | Choice |
| --- | --- |
| Board | 64 binary cells (queen or empty), the paper's N-Queens shape M×C = 64×2. No one-queen-per-row shortcut. |
| Energy | E(x) = Σ_{i<j} J[offset(i,j)]·x_i·x_j + b·Σ_i x_i |
| Parameters | 112 couplings shared by unordered relative offset (the paper's "relative position only" prior) + 1 shared bias = **113**, the count the paper's Table 1 lists. The model is not told which offsets attack. |
| Training | Pseudolikelihood at labeled solutions (paper Eq. 5), gradient written out by hand; zero init; full-batch SGD, momentum 0.9, cosine schedule from lr 2.0, 3,000 steps. No backpropagation through search. |
| Data | All 92 solutions, generated by backtracking in `nqueens.py`. Split by symmetry orbit: 3 of the 12 orbits are held out (seeded), so no held-out board is a rotation or mirror of a training board. Seed 0 holds out orbits 2, 4, 6: 68 train, 24 held-out. |
| Threshold | Highest training-solution energy + tolerance 0.5 (one half energy unit at β = 1). A sweep over other tolerances is in `results.json`. |
| How settings were chosen | Steps, learning rate and tolerance were picked during exploratory runs on this same seed-0 split. Those runs looked at held-out-orbit energies and invalid-set gaps, which the paper's protocol rules out. The held-out numbers below are therefore not a clean test, and they are still failures. A clean rerun would pick settings on a validation orbit carved from the training orbits. Solver β was chosen on training-solution puzzles only. |
| Solver | Random-scan Gibbs, not the paper's focused Gibbs search. Each chain starts from the clue queens only (other cells empty, as the paper's N-Queens init), clues clamped, resamples one free cell per update at inverse temperature β, halts when E ≤ threshold. Up to 20 chains × 2,000 updates. β = 1 for the learned energy, 2 for the hand-set one, both chosen on puzzles drawn from *training* solutions. |
| Hand-set baseline | **Not learned**: E = 2·(attacking pairs) − (queens), two unique weights. Every solution scores −8 and every other board scores higher, so threshold −8 is exact. |

## Run

Python 3.11+ standard library only; no numpy, torch or uv project.

```bash
python3 experiments/cram/train.py         # trains, evaluates, writes experiments/cram/results.json
python3 experiments/cram/test_nqueens.py  # unit tests, about 3 s
```

`python3 experiments/cram/train.py --help` lists the seed, split, training, tolerance and solver flags. The run is deterministic for a given seed and flags. These scripts are not part of `make test`.

## Results

One run of `python3 experiments/cram/train.py` (defaults, seed 0) on 2026-11-14, Linux, Python 3.14.7, Intel Core Ultra 9 290HX Plus laptop CPU, single-threaded. The host was busy with other work (load average 13–16), so wall-clock times are upper bounds. A second run gave an identical `results.json` apart from the timings. Full numbers: [`results.json`](results.json).

### Verifier

Invalid set: the empty board; every solution with one queen removed (`missing_queen`, 7 queens, no attack) or one added (`extra_queen`); every solution with one queen moved along its row (`row_shift`, two queens share a column); 2,000 seeded random column permutations that are not solutions (`permutation`, one queen per row and column, diagonal attacks only); 2,000 random 8-queen placements (`random_8`); 2,000 boards with each square a queen with probability 1/8 (`random_density`). Sets are deduplicated and contain no solution.

| | Learned | Hand-set |
| --- | --- | --- |
| Training solutions accepted | 68 / 68 | 68 / 68 |
| **Held-out solutions accepted** | **8 / 24 (33.3%)** | 24 / 24 |
| Invalid boards accepted, all sets | 3 / 17,025 (0.018%) | 0 / 17,025 |
| `empty`, `missing_queen`, `extra_queen`, `row_shift`, `random_8`, `random_density` | 0 accepted | 0 accepted |
| **`permutation`** | **3 / 2,000 accepted** | 0 / 2,000 |

Raising the tolerance to 1.0 accepts 16 / 24 held-out solutions and 5 invalid boards; no tolerance in the sweep accepts all 24 held-out solutions.

### Solver (held-out puzzles)

Each held-out solution gives three clue draws per clue count, 72 puzzles per row. "Solved" means a chain halted at a valid board containing the clues. "Wrong halt" means a chain halted at an invalid board. "Miss" means every chain exhausted its budget.

| Clues | Learned: solved / wrong halt / miss | Hand-set: solved / wrong halt / miss |
| --- | --- | --- |
| 2 | 34 / **37** / 1 | 72 / 0 / 0 |
| 4 | 25 / **16** / 31 | 72 / 0 / 0 |
| 6 | 24 / 0 / **48** | 72 / 0 / 0 |

Learned solve rates: 47.2%, 34.7%, 33.3%. Hand-set: 100% at every clue count.

### What failed, and why

- **Held-out solutions are mostly rejected.** The threshold comes from training solutions, and held-out orbits sit up to 2.0 energy units above the highest training energy. The descent itself often finds them: 27 of the 31 four-clue misses and all 48 six-clue misses ended on a valid board whose energy was above the threshold. The learned costs memorize which non-attacking offsets co-occur in the training solutions (mean −0.71, range −1.64 to +0.58), so solutions built from other offset combinations score worse. This is the "memorize associations between pairs of valid cells" behaviour the paper describes, meeting a split that holds out whole symmetry orbits.
- **Diagonals are under-learned.** Row and column couplings are large (2.7 to 6.7), but diagonal couplings are weak (0.22 to 3.59, the longest diagonal 0.22). In a solution every empty square already shares a row and a column with a queen, so pseudolikelihood can explain each empty square without the diagonal rule. That is why the only false accepts are `permutation` boards, and why the wrong halts in the two- and four-clue solver runs (re-checked with the same seed) were 8-queen boards with one or two diagonal attacks, plus 8 boards with 9 queens and one row and one column attack.
- The hand-set energy with two unique weights is exact under the same search: every held-out board accepted, no invalid board accepted, every puzzle solved. This matches the paper's caution that these puzzles fit a pairwise energy exactly. It is hand-set from the rules, not learned.
- **Sparsity did not fix it in a probe.** An unshipped probe added proximal L1 on the couplings (λ = 1e-3, 3e-3, 1e-2, bias unpenalized) to the same recipe. It looked only at weights and training energies, not at held-out or invalid boards. At λ = 1e-3 the non-attacking couplings shrank to −0.25…0. From λ = 3e-3 they were all zero, the 68 training energies were identical, and the bias was negative (−4.1, then −2.9 at 1e-2). So every attack-free 8-queen board, held-out solutions included, scores 8·b. But the diagonal costs also shrank, to a mean of 0.57, 0.19 and 0.17, with some exactly zero. A board whose only attack is one such diagonal then scores within the 0.5 tolerance of 8·b, and would be accepted (derived from the weights, not run on the invalid set). Only these three λ values were tried. Within them, sparsity trades the held-out failure for the diagonal blind spot.

The RFC's verifier success metric (zero false accepts, held-out solutions accepted) is **not met** by the learned energy under this protocol.

## What this is not

- Not a reproduction of the paper: no GPU, no Triton, no H200 timings, no Sudoku-Extreme, Maze-Unique or Baek et al. test sets. The paper's N-Queens protocol differs from the held-out-orbit split used here.
- Not the paper's search: plain random-scan Gibbs instead of focused Gibbs search, one β per energy.
- Not a general reasoner, and not evidence about one. N-Queens is a pairwise-exact constraint task (RFC 0002).
- Not wired into `ofl`, `make test`, or any Phase 2 verifiers or reward path.

## Files

- `nqueens.py`: solution generation, symmetry orbits, energy, PL loss and gradient, training, threshold, invalid sets, Gibbs solver.
- `train.py`: command line that trains, evaluates and writes `results.json`.
- `test_nqueens.py`: `unittest` tests. Solution count, offset sharing, fields vs energy differences, PL gradient vs finite differences, the hand-set energy's exactness, and a 500-step training run that must reject every row-shifted held-out board, keep held-out solutions as local minima, and accept at least one held-out solution.
- `results.json`: the run above.
